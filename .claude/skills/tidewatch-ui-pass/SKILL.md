---
name: tidewatch-ui-pass
description: Use when a Tidewatch UI/UX pass, popover audit, or a question or choice card over the chat, or the Waiting on you box's hint, is built or changed, or a right-click or tab menu item does nothing (Redraw, Draw avatar, Use letter).
category: native-app
---

A UI pass captures every screen and every popover or menu, each on its own, then sorts the findings into fix now or board. A screen-only check missed the repo menu, which the owner's screenshot then showed.

- List the surfaces before the first shot: the screens, popovers and menus, each with the dev switch that shows it. The list is in `references/surfaces.md`. A surface with no switch gets one in the same change, or it goes under Not verified. On General, a card below the fold needs its own scroll switch: `TIDEWATCH_DEV_SCROLL_KEEP_AWAKE`, `_CHECKLIST`, `_UPDATES` and `_SYNC` exist. On 2026-10-31 the Workflow card went under Not verified because the capture stopped at the top of General.
- Some dev switches, such as `TIDEWATCH_DEV_PANEL`, reach only the first tab, so select the tab a surface belongs to before you shoot.
- The question card has its own switches. `TIDEWATCH_DEV_ASK=1` puts a stand-in three-option question in the Reader once. As steps of `TIDEWATCH_DEV_QUESTION`, `open` and `fold` open and close the full card. The card opens folded, and `pick` and `next` do nothing while it is folded, so a capture of the options starts with `open`. The steps are listed in `docs/dev-switches.md`.
- A `TIDEWATCH_FAKE_` switch shows that a screen draws, not that the app writes the data behind it. Before you call a fake-fed state working, grep the code that writes that state. If nothing writes it yet, name it under Not verified in the same reply and say the switch is the only proof. On 2026-10-31 a panel's "by Tidewatch" step mark drew only under its fake switch: the worker's hand-back said steps ticked by Tidewatch read done, and the lead found that nothing in the app marks a tick yet.
- The Poofed Meeseeks summary draws in a background run with `TIDEWATCH_FAKE_MEESEEKS=poofed` and `TIDEWATCH_DEV_SELECT=2` (2026-11-04). The fake only draws the view, so the saved record needs its own model test.
- Capture in a background run with the screenshot switch, a throwaway `HOME`, and a `ZDOTDIR` with a neutral `PROMPT`, so no user name or real path shows in a pixel.
- Do not edit app source to hide the parts a shot does not need. On 2026-11-04 a shot in a window too short for the page added `if false &&` to three conditions, built, shot, and restored from a scratch copy. Shoot the part that fits, or name the rest under Not verified. Set the window with `TIDEWATCH_DEV_WINDOW` (a width and a height in points, 600 to 4000 each). Three runs at 1280 wide exited 124 with no file that day, while 1100x900 wrote its shot on the first try: try a smaller size before a third rerun of the same one.
- A background capture cannot open a tooltip. On 2026-11-01 `TIDEWATCH_DEV_HOVER` opened none, not even the existing main-tab tooltip. A headless hover test covers the tooltip's behavior; its look in a real window goes under Not verified until someone sees it.
- A capture with agent tabs needs no real agent. Keep a stand-in kit in a folder outside the repo that survives cleanups, not a session scratchpad, which a crash or a cleanup can wipe. The kit is a `claude` script first on PATH that answers `--version` with `2.1.310 (Claude Code)` (the version probe needs that) and then runs `sleep 60`, so the tab stays up. Add a throwaway copy of the demo repo, and a run script that sets `HOME`, `ZDOTDIR` and `TIDEWATCH_HOME` to one throwaway folder, `TIDEWATCH_DEV_TRUST=no`, `TIDEWATCH_FAKE_AMPHETAMINE=off` and `TIDEWATCH_SCREENSHOT`, then runs the built app with `--no-restore` on the demo repo. Use `TIDEWATCH_SCREENSHOT_WAIT=6` or more, since profiles probe in the background. Seed the first agent tab's ledger with `TIDEWATCH_DEV_PROGRESS` set to a markdown ledger file. Name the stand-in beside each shot.
- Shoot each surface in every state it can show (working, waiting, needs you, done, empty, a long name or path), at the owner's narrowest and widest widths. A shot goes stale once a later commit touches its surface, so retake it before the PR is marked ready.
- A capture can hang and then succeed on a rerun. `timeout` exits 124 when it hangs. On 2026-11-01 the narrow meter shot hung several times, once on a new build. Rerun it and tell the owner about the retry. A hang is not a layout result.
- A headless layout test is a guard, not the proof of a layout. Its window size and fonts can differ from the app's, so a control can wrap in the test where the real window keeps it on one line. On 2026-10-31 the profile editor's test wrapped the permission control at a width where the real app fits it inline. The capture of the real build at each width the owner uses decides the layout, and the test only catches the regressions it measures.
- Read each capture at full size, word by word. Check plurals ("1 tabs"), text past its box, the selected-row look (a tint with a teal name and no 2 px edge bar, the owner's pick on the unify board, row 11 A; a bar still on the row means that change is not in yet), icon and shortcut alignment, and the order of lists and pickers.
- Name the commit each capture was taken on, and check it against the branch head before you send it: a shot taken before the branch's last commit is stale, so retake it or say so. Before you write that a capture matches an approved board, open the board and the capture side by side. A worker's "I did not set the board's card beside them" stays under Not verified until you do. On 2026-11-01 the lead's reply said the captures matched option A, with no side-by-side read in the trace, and the worker had said its shots came just before its last refactor commit.
- Measure an edge by number, not by eye. A guide line only shows where an edge sits. Scan a band of rows instead: keep the brightest value of each column, then report the first column that differs from the band's first column by more than 10 levels. The band has to start on background, since its first column is the reference. Use `-statistic Maximum` for bright content on the dark ground, and `Minimum` for dark content on a light ground. For a 760 by 110 band at 280,0 in a shot named SHOT.png: `magick SHOT.png -crop 760x110+280+0 +repage -colorspace Gray -statistic Maximum 1x110 -gravity center -crop 760x1+0+0 +repage -depth 8 txt:- | awk -F'[ :,()]+' -v x0=280 'NR>1{ if(NR==2) bg=$3; d=$3-bg; if(d<0)d=-d; if(d>10){print $1+x0; exit} }'`. Check the scan on a capture whose edge you already know before you trust its number, and keep the script beside the stand-in kit, not in a scratchpad.
- Split the findings in two. A pure alignment, spacing, wording or plural fix goes in now, with a headless test that fails on the old code. Anything that changes how a surface looks (colour, icon, weight, layout, a new control) goes on an Artifact board first. Render the board and look at it (see `ui-patterns`), then wait for the owner's pick before you change the look. The Reader and first-message box follow `tidewatch-chat-composer`.
- Keep each board's source (its HTML, screenshot crops and build script) beside the stand-in kit, and record that path in the ledger. On 2026-10-31 the unify board's build script and crops were written only under a session scratchpad, which a cleanup can wipe. `ui-patterns` asks for a permanent source folder; this is the Tidewatch one.
- Sizes come from one scale. Add no height or font size while you fix (see `tidewatch-control-sizes`).
- A fix in a shared piece reaches every screen that calls it. Before you change one, such as `disclosure()`, a selection row or a button look in `screen_kit.rs`, grep its callers and shoot each one. On 2026-10-31 a wrap fix in `disclosure()` (the Advanced label) also reached the trust, leftover and take-over views. Name any caller you did not shoot under Not verified.
- A finding in a widget that Kelp or stdusk draws, such as the file view's diff body, the graph or the terminal grid, is not fixed with a local override. Name it under Not done with its sibling repo (`../kelp` or `../stdusk`), and fix it there (see `.agents/rules/project.md`, Sibling repos). On 2026-10-31 the restyle left the file view's diff gutter and sideways scrollbar as they were, because kelp-ui's diff body draws both, so the scrollbar still showed in the capture.
- Close with three lists: surfaces captured, surfaces not captured and why, and findings fixed versus on the board. Name each uncaptured surface under Not verified.
- An approved board option that the build leaves out goes under Not built in the reply, with its reason. It stays a todo step with that reason in the ledger until it ships, so the owner does not find the gap in a capture. On 2026-11-01 the running-agents list left out opening a sub-agent's chat, and the reply named it under Missing from the board.
- Send the owner each shot that a yes depends on with `SendUserFile` in one call (load it first with ToolSearch, `select:SendUserFile`): `display` `render`, `status` `proactive`, and a caption that says which state each file shows. Say in the reply that nothing merges before the owner's yes. On 2026-11-01 the lead sent three question-card captures (folded, open and narrow) this way, with the merge held for a yes.
- Decided looks are written here, so a later pass does not ask again. The owner picked option A, Calm (one-line rows, colour square, check), for the menus and popovers board on 2026-10-31. Build that option for the menus on that board: each repo is one line, a small square in that repo's colour (`overview::repo_ink`), the repo name, and a teal check at the right edge on the repo on show. Open repo and Close repo sit under a divider as plain rows. Other options on that board stay open until the owner picks them. The selected row in every list is one `selection_row` look in `screen_kit.rs`: a teal tint with the name in teal and no bar on its edge (the option the owner picked for the selected row on the unify board). Do not bring the edge bar back, since the owner rejected that pattern as too AI-looking. Change the `selection_row` line in `.agents/rules/project.md`, which still names a 2 px bar, in the same change.
- An Overview card has a fixed height that a test locks. Put extra detail, such as the goal line, in the tooltip. A third line on a card reflows every lane (decided 2026-11-03, PR 342).
- A menu or popover restyle keeps every item, action and key the old one had. The owner's standing rule, as the 2026-10-31 worker brief quotes it: "I want everything to be possible." Do not drop an action to make a menu tidy. A removal is the owner's call.
- A menu item that does nothing, with no toast, is usually a stored value the reader never finds. egui's temp data is keyed by exact type. A write of `Option<(u64, &Choice)>` and a read of `Option<(u64, Choice)>` both compile, and the read returns `None`. Give the write and the read one typed pair of functions (a `choose` that takes a `Choice` by value, and a `take_choice` that reads it back). Loop with `for &(label, choice) in list` so each item is copied, not borrowed. Test it in the headless frame harness (see `testing.md`): find the item by its painted label, click its centre, then assert the reader gets the value. On 2026-11-03 Redraw, Draw avatar and Use letter failed this way since be7c5d03. The fix is PR #346: check it merged before you say it ships.
- A question or choice card over the chat opens folded to one line: the question cut to fit, the option count, and an Answer button. Answer, a click on the line, or Enter with the reply box empty opens the full card, and its fold button closes it again. The owner reads the chat before deciding (owner, 2026-11-01: "I first need to read before I decide else I have no context."). Digit keys pick an answer only while the full card is open. The owner picked this as option A on the question-card board (2026-11-01). When a card closes too early or stays open against Claude's menu, see tidewatch-question-menu.
- Quick-reply chips (Yes, No) sit directly under the question they answer. Draw them right after the row that holds the newest agent message (the `chips_after` anchor), before any later note, card, queued message or PR tail. On 2026-11-02 the owner read the Yes and No chips as Tidewatch asking about the avatar, because a quiet note ("Tidewatch asked for an avatar") had landed between the question and its chips. Check the order in a capture taken with such a note present.
- When the owner names where a control goes, build it there. Repo-scoped actions go in that repo's new-tab form, not in an Overview card. Owner, 2026-11-03: "I think this should just be an option under new tab under a repo, no?" The Recently closed card came out for that reason (PR 342). The rule above still holds for the new control's look.
- Start and stop are visible buttons, never only inside a `...` menu. A row's play or stop sits at its right end, and a header uses the same spot. Moving an action from a menu to a button keeps the action, so the menu rule above does not block it. Owner, 2026-11-03: "I would also like to have like a play / stop button rather than text (and stop currently is hidden under kebab)." The service rows follow this (see `tidewatch-services`).
- The Progress panel's **Waiting on you** box has two sources: report questions, which get a card above the reply box, and the chat's end-block Needs you lines, which get no card. A hint that names a place on screen must match its source: chat lines say **Reply in the chat**, and only report questions say "Answer above the reply box". Check each hint in a capture of both sources.
