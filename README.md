# Tidewatch

A desktop app for macOS and Linux that runs AI coding agents side by side, one git repo per window.
Every tab is its own git worktree (a separate checkout on its own branch) with an agent running in
it, so several agents can work on the same repo without touching each other's files. You watch them,
read what they did, comment on their diffs and decide what ships.

The terminal is on the left and the history of that worktree on the right. Click a commit to open its
files in the tree, then a file to see its diff where the terminal was; the agent keeps running, and
Esc or the Terminal chip takes you back. Built by [HoboWare](https://github.com/Hobo-Ware) from the parts of
[Kelp](https://github.com/Hobo-Ware/kelp) (graph, diff, review) and
[stdusk](https://github.com/Hobo-Ware/stdusk) (terminal, tabs, quake window).

Status: v0.1.49. Showcase page: [tidewatch.hoboware.dev](https://tidewatch.hoboware.dev).

## What it does

- **Worktree tabs, one agent each.** A new tab is a form in the tab itself: pick an agent, a Meeseeks or a plain shell, name the worktree and the branch it starts from, write the first message, and Start makes the worktree and starts Claude Code, Codex, Gemini CLI or Copilot CLI in it. Profiles set the agent, model and permission level, from read only up to a YOLO level that asks first. An agent tab can push its own branch, but never the repo's default branch, a tag, `--all` or `--mirror`: a guard refuses those with a one-line message. The first message is written in the same box as the Reader's reply, with pictures, files and `@` picks of the repo's files. Once the agent knows its task, the tab takes a short kebab-case name (`pkce-auth-security`) and an icon from a bundled Lucide set that matches it; a name you set with `/rename` always wins, and an agent you ask in chat to change its icon does so.
- **Remote control.** A switch in the new tab form (off by default) starts Claude Code with `--remote-control` or Copilot CLI with `--remote`, so the session can be driven from the Claude app or GitHub mobile. A running tab shows a Remote pill with the session name, Copy link (once the CLI has printed one) and Turn off, which applies the next time the agent starts. Codex and Gemini CLI have no per-session flag, so the row is disabled for them.
- **New tab defaults.** Settings, General, New tabs sets what the form opens with: the agent, the permission level (YOLO too, where it is allowed; in Other the form opens at Auto and says so), remote control, whether to start from the current or the default branch, and which side of the right card shows first. They live in the `[new_tab]` table of `settings.toml`, and every tab can still change them.
- **Worktree setup.** Settings, Worktree setup holds a small recipe per repo (in `~/.config/tidewatch/worktree-setup.toml`, never in the repo): gitignored files to copy from the main checkout (`.env` files are offered with one click), folders to link (such as `node_modules`; nothing is ever installed through a link), sharing the main checkout's `target` folder with every Rust worktree, and a generator command that runs in the new worktree and shows as a job. A missing file is a note, never a failed tab. When a tab's pull request merges, its card checks that nothing would be lost (no uncommitted changes, no untracked files, no commits the pull request lacks), lists ignored files that would go, and offers Remove worktree and branch.
- **Reader view.** An agent tab reads as a chat: your messages on the right as formatted text (an image shows as a chip, a link is clickable), each finished agent turn on the left as its final answer, with the notes before it folded under an `N updates` chip and its commands, edits and reads counted in one row of chips (a click lists them). Your answers to the agent's questions come back as a `Your answers` card, and a background task note is a quiet row. One shortcut flips to the raw terminal.
- **One send line.** A reply you type while the agent works is held and typed when its turn ends, one message per turn (never merged). Held messages sit in a card under the chat with Edit, Delete and Send now. Up and Down in an empty box walk through what you sent before (100 per tab), a half-typed draft is kept, a Stop button beside Send (and Esc in an empty box) interrupts a working agent, and hovering your own bubble shows a small toolbar under it with Edit, Copy and Send again as icons. A message the transcript never shows reads `Not seen by the agent` after 2 minutes, with Send again and Dismiss. Held messages are not kept across a restart; the draft and the history are.
- **Files in the sentence.** A picture pasted with Cmd+V, a file dropped on the box and an `@` pick (the repo's files, fuzzy matched) each land at the text cursor as a chip, never at the end or in a row above the box, and the sent message carries each path at that same place. Backspace takes a chip whole. The same box in the new-tab form works the same.
- **Progress.** The right card's Progress tab shows the agent's progress report in two to five stages the agent names for the task, and reads top to bottom: the goal, Waiting on you (the question, answered above the reply box), Now (the agent's note or current step, how many steps are done, how long ago it was updated and the lead job's bar), Waiting for (the job, pull request, date or event it waits on), one row of stage bars, the steps by stage (a step reads `checked` when Tidewatch ticked it or ran what it names and `claimed` when only the agent says so; a blocked reason is in amber), Coming up (the report's dated items), Decisions, Not verified and Verified, the done check and Links. A question the agent asked with its question tool and you answered ticks the step it is about. A report older than the running turn shows dimmed under `From the last turn`. The tab shows an orange dot while there is a new question or a link that needs action.
- **Changes and commit search.** The right card switches between Progress, Changes and History. Changes lists the uncommitted files in three groups, Staged, Changed and New files, each with its status letter and line counts and a footer with the totals; a click opens the file's diff where the terminal was. It only views: nothing there stages, discards or commits, the agent does that. History has a search field above the graph (Cmd+F, Ctrl+Shift+F on Linux): commits that match the message, author or id stay bright with the match marked, the rest fade, Enter and Shift+Enter jump between matches and Esc clears it.
- **Notes on diff lines.** Leave a note on a line of the diff, then send the notes to the agent as one message.
- **Meeseeks.** The new-tab form's Meeseeks kind takes one task per line and opens a tab, with its own worktree, for each. A Meeseeks has one job: when it says it is done, Tidewatch checks the work (the tree is clean with a commit, the repo's tests pass, and, when you ticked it, a pull request is open, which the Meeseeks pushes and opens itself), then ends the agent, removes the worktree folder and keeps the branch. If it fails three checks, runs 40 turns or 60 minutes, the tab turns orange and waits for you: Take over or Give up. The tab stays as a read-only summary: the task, how long it took and when it ended, the four checks with their results, what the agent said, the pull request link, the branch with its commits ahead and changed files (read from the branch, so a deleted branch says so), the last turn and the progress report stages, and one Close button. It survives a restart, and what poofed today is listed on the Overview, where a row opens its summary.
- **Done check.** When an agent says it is done, Tidewatch looks at what is really there: the work is committed, the branch is pushed, the pull request is open or merged with its checks passing on the pushed commit, the repo's tests pass (Tidewatch runs the repo's test command itself in the tab's worktree and the card shows `Ran cargo test --workspace: passed in 134 s`; a failed run goes back to the agent with the end of the output), and the agent's progress report lists nothing unverified. A card on the tab says Done, Blocked (each failed check in one line, with Ask agent to fix) or Not verified. A tab with no pull request makes no GitHub call. Settings, General, Done check turns it off.
- **YOLO and Meeseeks act on their own.** A YOLO agent or a Meeseeks is told to decide and proceed on everything except product design and architecture choices (those it asks with the question tool, while it keeps working on the rest), so nothing waits for a click that an agent can do: their pull request mode is Auto for the fix jobs whatever the default says (the Settings ticks still apply and you can still change it in the strip), and in Auto comments, requested changes, failed checks and conflicts go to the agent when it is idle, with the cards kept as a record (`Sent to Builder`) and no Ask or Reply buttons. Auto sends up to 10 times per pull request on such a tab, then pauses with one line instead of falling back to Ask me. The done check's fix note and an item that is due go to a YOLO agent the same way. Pushing the branch and opening the pull request is one more job Auto may do (Settings, General, GitHub, or a tab's PR strip), off by default and never forced on a YOLO or Meeseeks tab: with it on, Tidewatch asks the agent to push the branch and open the pull request itself, once per stretch of work, and commits made after a merge go to a new branch and a new pull request. Comments with nothing to act on, such as a review bot's receipt or a deploy bot's status, are no card on any tab.
- **Pull requests.** Tidewatch never pushes a branch and never runs `gh pr create`: the agent does both. When commits are ready, a card above the panes says how many and offers `Ask <Profile> to open a PR`; the message names the branch, the base and the commit count, and asks for a title and body the agent writes. The pull request opens as a draft unless the repo's way of working says ready. The card then reads `Asked <Profile> to open the pull request` and Tidewatch looks for the pull request when the agent goes idle.
- **Your repo's way of working.** Each repo gets a profile (rebase or merge to catch up, fixup commits or new commits for fixes, draft or ready pull requests), detected from your rules files and confirmed once on a card under the tab strip or in Settings, General. Every message Tidewatch sends an agent about a pull request names only the method the profile chose, and the done check's proof switches (tests run by Tidewatch, verified means rerunnable and scope, on by default; a fix comes with a test, off by default) live there too.
- **Live links.** Links the agent shares (and the pull request and issue links in its messages) collect in a Links card at the bottom of the Progress panel. A pull request or issue shows draft, checks, review, conflicts, close reason, comments and GitHub's update time, kept live by GitHub's own events where a forwarder runs and polled otherwise. A board of four links or more has chips for type (All, PRs, Issues, Artifacts, Docs and web) and state (Open, Needs action, Done), each with a count, and a search box; rows sort needs action first, then open by last change, then done. A repo `gh` cannot read reads `no access`, a deleted pull request `gone`.
- **Tokens.** A tab's tooltip and its Overview card say `1.2M tokens · 96% cached · 18 turns` and what Tidewatch's own messages cost it, and the status bar shows the active tab's tokens. Claude Code and Codex report them; Gemini and Copilot do not. Settings, General, Token budget has save mode, which holds Tidewatch's own automatic sends and new Meeseeks near a plan limit; Claude Code does not give its plan limits to other programs yet, so it has nothing to watch and does nothing.
- **Closing a tab.** Closing a tab always asks. Settings, General, Tabs sets which button Enter presses in that dialog: `delete` (the default) deletes the branch, `keep` keeps it. A worktree with uncommitted changes has no default button.
- **Overview and focus mode.** Overview lists every tab with its state: working, needs you, done or failed. Focus mode hides the history so the terminal gets the whole window.
- **Session restore.** Quitting saves your tabs. The next launch brings them back and resumes the agents where the CLI can. `--no-restore` or a setting turns it off. `resume_agents` in `settings.toml` (Settings, General, Startup) is `auto` (run the resume command), `prefill` (type it and leave Enter to you) or `off` (a plain shell); when its agent crashed on its own, or Tidewatch crashed again within five minutes of a launch, the command is typed and never run (one crash of Tidewatch resumes as the setting says). A command too long to type is not typed: the tab reads Stopped, with an Agent is not running bar and a Resume button that runs it. The hook settings of a Claude tab live in a private file in the tab's state folder, so the typed line shows no token. A YOLO tab resumes with the same permissions it ran at, but its command is always typed and waits for Enter, whatever the setting (`off` still gives a plain shell). On macOS, Settings, General, Startup also has Open at login, which asks the system and keeps no setting of its own.
- **Settings sync.** Settings, General, Sync keeps `settings.toml` and `profiles.toml` in a private GitHub repo you own (`owner/name`, or a full git address). Turn it on and Tidewatch pulls at launch and pushes a few seconds after a setting changes, with your own git login: nothing is stored and nothing goes through a Tidewatch server. Folder trust (`trust.toml`), the app state under `~/.tidewatch` and the sync choice itself (`sync.toml`) never leave the Mac. Local changes are committed before anything is merged, and when the repo changed the same setting this Mac keeps its own and says so. A repo that does not exist yet is created, private, only when you click Create private repo (it runs `gh repo create --private`). What a pull brings in applies at once, with no restart (interface size, window height, hotkey, drop-down, profiles and the rest), and the card says `Settings updated from <repo>`; an open Settings page with unsaved edits keeps them, and tabs that are already running keep the profile they started with. Sync now runs it at once.
- **Background fetch.** Open repos are fetched in the background every 5 minutes by default, so the ahead and behind counts stay fresh. Settings, General, Git sets the interval (1, 2, 5, 10, 15 or 30 minutes) or turns it off. A failed fetch shows a quiet `Fetch failed` note in the status bar.
- **Touch ID for Amphetamine.** The keep-awake button (Amphetamine) can ask for Touch ID instead of your password when it starts lid-closed mode. Settings, General, Keep awake has a one-time Set up for it, which installs a small helper through one password prompt.
- **Terminal links.** Links in the terminal are clickable, as in stdusk.
- **Folder trust.** On first launch Tidewatch asks once before it marks its worktree folder as trusted in the agent CLIs' own config files, so they stop asking in every new worktree. It changes nothing without a yes, and Settings can undo it.
- **House style.** One file, `~/.config/tidewatch/house-style.md`, tells every agent how to write its answers (summary first, file references, a Done / Needs you / Next block). Edit it freely: Tidewatch never overwrites it. Settings, House style opens it in your editor and can put the default text back.
- **Profiles.** The profile editor uses one kind of control: agent, effort (Default, Low, Medium, High, Extra high, Max) and permission level are segmented choices (chips in a narrow card), and a muted line under each says what the selected value does.
- **Quake window, palette, updates.** A drop-down window on a hotkey, a command palette, and update checks; see below.

## Quake window

Tidewatch drops from the top of the screen on `Ctrl+Alt+Grave` (stdusk keeps `Ctrl+Grave`, so both can run) and hides when you click elsewhere. There is a menu-bar item with Show / Hide, Overview, Settings and Quit. Settings, General, Window turns the drop-down off for a plain window, records a new hotkey (click the key caps and press the keys), sets how far the window drops (`height_pct` in `[window]`, 20% to 90% of the screen, half by default) and moves the panels: History beside the terminal (the default) or History and the diff below it (`panels = "below"` in `[window]`). `tidewatch <path>` for a repo that already has a window brings that window forward instead of opening another. `tidewatch --toggle` shows or hides the running windows: on Wayland, which has no global hotkeys, bind it to a desktop shortcut. On Linux the plain window draws its own frame: the tab strip is the title bar (drag it to move the window, double-click it to maximize), the window buttons follow your GNOME button layout, and the edges resize.

Settings, General, Terminal picks the terminal's font: Built-in, the default, or any installed family from a search (`font` in `[terminal]`, empty for the built-in one). It applies at once and changes only the terminal; the rest of the window keeps its own fonts. Pick a Nerd Font there if your prompt theme draws icons.

## Keyboard

`Cmd+Shift+P` (`Ctrl+Shift+P` on Linux) opens the command palette: type to filter every command, the other open tabs and each agent profile, with a result count, group labels and the letters you typed marked in each result; Enter runs, Esc closes. Settings, Shortcuts, lists every chord for the platform you run on. [docs/shortcuts.md](docs/shortcuts.md) has both columns; a test keeps it equal to the command table in the code. On Linux a plain Ctrl chord would reach the shell, so it uses Ctrl+Shift or Alt where macOS uses Cmd.

`Cmd+=` and `Cmd+-` (`Ctrl+Shift` on Linux) set the interface size from 80 to 150 percent, and Settings, General, Window has the same choice.

## Updates

Tidewatch checks GitHub for a new release about once an hour and when its window comes back into focus. On macOS, installed from the Homebrew cask, it runs `brew upgrade --cask` in the background and the pill in the top bar asks for a restart. Everywhere else (Linux, a macOS copy that was not installed with Homebrew) it only says "Tidewatch X is out" and the pill opens the release page. Settings, General, Updates has Check now and the two switches (`[updates]` in `settings.toml`: `check`, `install`). A check that fails on its own is silent; Check now shows why. After an install, Restart starts the new version and hands it every terminal: shells and agents keep running where they were (no resume), and the new window picks up the same tabs and repos. If the hand-over cannot complete, the old window stays open and says why; session restore still covers a quit or a crash.

Moving tabs from stdusk: its "Move tabs to Tidewatch" hands its live panes over, and each becomes a shell tab here, in the group of the git repo it was in, still running.

Agent sessions running in other terminals: the Overview lists Claude Code, Codex, Gemini and Copilot sessions it finds (Running elsewhere). A process cannot be pulled out of another terminal, so Move here ends it once it is idle and resumes the same conversation in a tab with the same flags; one in stdusk moves live through stdusk's own button. Also in the palette: Move sessions to Tidewatch.

## Install

- macOS: `brew install hobo-ware/tap/tidewatch`
- Linux: the `.tar.gz` or the `.AppImage` from the [latest release](https://github.com/Hobo-Ware/tidewatch/releases/latest)

## Build from source

```sh
cargo run -p tidewatch -- [path]      # run
scripts/bundle-macos.sh               # universal Tidewatch.app in target/dist
scripts/package-linux.sh              # x86_64 Linux tarball and AppImage in target/dist
```
