Hoboware · concept · Oct 2026 Kelp's graph + stdusk's terminal + agents in worktrees

Tidewatch: one window to run AI agents, one repo at a time.

Each repo gets its own window space. Each tab inside it is a fresh git worktree with an AI agent running in it. You watch the agent work in the terminal, see the history of that one worktree below it, and read the changes on the right. An Overview lists every agent in every repo. A tab can also run a whole workflow (work, review, refactor), each stage with its own agent, model and permissions. There are no fetch, pull or push buttons. The agent does that work, or you type it.

Reader view

Read the agent like a chat, keep the terminal underneath

Agent tabs open in a Reader by default: the same session, drawn as formatted markdown with real fonts, headings, checklists and buttons. It is only a view. The agent still runs in its real terminal, the text comes from the agent's own session file, and anything you type or click is typed into that terminal. ⌘⇧T flips to the raw terminal at any time; split panes stay plain terminals.

How it stays a terminal

  • The agent's real interface runs in a pty. Nothing is replaced or wrapped, so slash commands, menus and every CLI feature keep working.
  • The Reader tails the CLI's own session file: Claude Code ~/.claude/projects/…/<session>.jsonl, Copilot ~/.copilot/session-state/<id>/events.jsonl, Codex rollout files (stdusk already reads them). Gemini's format is a spike.
  • Replies and buttons become keystrokes into the pty (bracketed paste for text, the matching key for Yes / Always / No), timed by the status hooks.
  • Markdown is drawn with egui_commonmark (0.24 matches egui 0.35). Tool calls fold into one line you can open.
  • Copy gives plain text, and the terminal is one key away when the Reader gets something wrong.

Other ways, not picked

  • Run agents in a structured protocol (ACP or stream-json) instead of their terminal UI: exact events, but you lose the real terminal and CLI features, and three of four CLIs need third-party adapters.
  • Prettify the terminal grid (nicer font, spacing, hide box drawing): no parsing, but it is still monospace and cannot show real markdown.
Names

Five names, one pick

Tidewatch is the pick. The others stay here for comparison; click one and the mockup above uses it. I have not checked trademarks or Homebrew for clashes yet.

How a tab works

One tab = one worktree = one agent

Tabs never mix repos. Opening a tab inside a repo always makes a new, separate worktree, so two agents can never edit the same files.

Open a tab

Press ⌘T in a repo. Pick a workflow or a single profile, set the permission level, write the task, pick the base branch (default: main).

Worktree is made

git worktree add -b agent/<name> in ~/.tidewatch/<repo>/. The profile's setup step runs (for example npm ci).

Agent starts

The profile's CLI starts in the worktree with the task as its first prompt. The tab shows its logo and status.

You watch

Status on the tab: working, needs you, done, failed. A notification fires when an agent needs you and the window is hidden.

You review

Split the terminal to run the app or tests in the same worktree. Commits appear in the graph on the agent's lane. Uncommitted work shows as a live row on top. Comment on a line in the diff and send it to the agent.

Close the tab

Its terminals close and the worktree is removed. If the branch has work not on main, you choose: keep the branch or delete it.

Profiles

Pre-seeded profiles, with every permission level

On first launch Tidewatch looks for agent CLIs on your PATH and creates these profiles for the ones it finds. Each profile picks an agent, a model and a permission level from Read only to YOLO. Tidewatch turns the level into that CLI's real flags. Edit one below and the mockup's new-agent dialog uses it.

The five levels, per agent







  

    Workflows
    
Work, review, refactor as one pipeline

    
A workflow is a list of stages. Each stage is a contract: what it does (the prompt), who does it (agent, model, permission level), and the gate it must pass before the next stage starts. All stages run in the same worktree, one after the other, in the tab's agent pane. A failed gate can send the work back to an earlier stage, a set number of times.

  

  

  

  

  

    

      
The stage contract

      
    
        
  • Inputs: the prompt can use {task}, {base}, {branch}, {prev} (the last stage's summary) and {findings} (open review comments).
    • 
        
  • Outputs: Work, Fix and Refactor leave commits. Review leaves findings (file, line, blocking or nit, text). Findings become threads in the diff, the same threads you write.
    • 
        
  • Gates: tests pass (the repo's test command), a new test fails, no blocking findings, or you approve. Tidewatch checks the gate, not the agent.
    • 
        
  • On fail: go back to a named stage with the findings, up to the loop limit. Then the tab stops and asks you.
    • 
        
  • Permissions: each stage has its own level. Review stages default to Read only, so a reviewer cannot "fix" what it reviews.
    • 
      

    

    

  






  

    Functionality
    
What is in, what comes next, what stays out

    
The rule for v1: the UI shows and monitors. It only changes things where a click is clearly faster than asking an agent.

    Inherited
    
Everything else works like stdusk and Kelp

    
Tidewatch should feel like a sibling of the two apps from the first launch: same window behavior, same updates, same keys.

  

  

    

      
From stdusk

      
    
        
  • Quake or window: drops from the top edge on a global hotkey, hides on blur, follows the active Space and screen. Or a normal window.
    • 
        
  • Restart keeps your shells: after an upgrade the old window hands live terminals and agents to the new one.
    • 
        
  • One instance: tidewatch ~/Git/repo opens a tab in the running window.
    • 
        
  • Settings GUI: fully keyboard-operable, color schemes with live preview, light and dark that follow the OS, settings sync to your own git repo.
    • 
        
  • Command palette, scrollback search, links, image paste, file drop, theme reports to CLIs like Claude Code.
    • 
        
  • Notifications when a long job finishes or an agent needs you while hidden, and the menu-bar item.
    • 
      

    

    

      
From Kelp

      
    
        
  • Self-update in the background when installed with Homebrew.
    • 
        
  • Session restore: reopens last time's repos and tabs.
    • 
        
  • Speed rules: 0% CPU when idle, only visible graph rows drawn, git never blocks the UI.
    • 
        
  • Avatars: GitHub, then Gravatar, then initials.
    • 
        
  • Accessibility: visible focus, full keyboard use, a contrast floor on every theme (from stdusk), reduced motion respected.

    Building it
    
Mostly parts we already have

  

  

    

      
Reused

      
    
        
  • From Kelp: kelp-core as a git dependency. Graph lanes, diff, status, worktree listing. Its speed rules carry over (only visible rows are drawn, 0% idle CPU).
    • 
        
  • From stdusk: the terminal (alacritty grid, pty, OSC progress), split panes from pane.rs, AI CLI detection from procwatch.rs, repo grouping from repo.rs, session handoff on upgrade.
    • 
        
  • Same stack: Rust, egui, gitoxide for reads, git CLI for writes.
    • 
      

    

    

      
New

      
    
        
  • Worktree manager: create on tab open, remove on close, find leftovers after a crash.
    • 
        
  • Profiles and workflows: TOML files, first-launch detection of agent CLIs, the permission-level mapping per CLI, per-repo overrides.
    • 
        
  • Workflow runner: starts each stage's CLI in the agent pane, checks gates (test command, findings, approval), loops back on failure.
    • 
        
  • Agent status: uses the CLI's own hooks where they exist (Claude Code has Notification and Stop hooks). Falls back to OSC progress, title changes and quiet output time.
    • 
        
  • Comments to the agent: pasted into its terminal as Markdown with bracketed paste. Proposed: the app also runs a small MCP server per agent with a reply tool, so the agent can answer inside the thread.
    • 
      

    

    

      
Decided

      
    
        
  • Name: Tidewatch.
    • 
        
  • Repo: a new repo in Hoboware, Hoboware/tidewatch.
    • 
        
  • Worktrees: ~/.tidewatch/<repo>/<tab>, out of the code folders, no gitignore entry needed.
    • 
        
  • Layout: B, terminal full width, with focus mode.
    •
