# Tidewatch - dev switches and live checks

The `TIDEWATCH_DEV_*` and `TIDEWATCH_FAKE_*` switches, how to check single-window, restart,
stdusk hand-over and session restore in the background, and the key map. Read it before a
screenshot or live check. The safety rules (background runs only, throwaway homes, no real
GitHub) are in `.agents/rules/project.md` and always apply.

One window for the app: `tidewatch <path>` hands the path to the running window and exits (no second window); the window adds a folder it does not hold as a repo (its own tab group, main shell and saved tabs, chip menu or the next/previous repo chords to switch) and brings forward one it holds. A launch with no path reopens the repos of the last window (`dir`, `also`). To check it in the background: start a `TIDEWATCH_BACKGROUND=1` run with a short throwaway `TIDEWATCH_HOME` and `TIDEWATCH_DEV_QUIT`, wait for `.state/instances/tidewatch.sock`, run `tidewatch <other repo>` with the same home (it hands over and exits at once, so only do it once the socket exists), then read both repos in `session.toml`. A launch with no path and no git repo around it (Finder, or the `open -n` of the update Restart button, both start in `/`) opens the last-used folder; a window that is closing answers `closing` and the new launch waits for its socket, so a restart never hands its folder to a dying window. Restart to update keeps every shell and agent running: the old window sends its layout and ptys to the new one (`--handoff <socket>`, `handoff.rs`), the new one claims the app socket only after it confirmed, and on any failure the old window stays open. A layout with a group per linked worktree (made by an older version) comes back as one group of the main repo: `app/merge_groups.rs` folds groups of one repo whenever the set of group folders changes and once at the start, a main shell that runs a command staying as a shell tab; check it with an old-style window (groups opened with `Workspace::open`, a throwaway build) restarting through `TIDEWATCH_DEV_RESTART` and read `session.toml` after. The pill needs a foreground window, so check it with `TIDEWATCH_DEV_RESTART=<seconds>` in a `TIDEWATCH_BACKGROUND=1` run with a short throwaway `TIDEWATCH_HOME` (the new window is started directly, inherits the environment except the dev switches that open or restart tabs, and `TIDEWATCH_DEV_QUIT` ends it): read the pty children's pids before and after (same pids, parent 1) and post a hook to the old URL and token (200, and `TIDEWATCH_DEV_STATUS_LOG=1` shows it); kill everything you started. Moving tabs from stdusk (its "Move tabs to Tidewatch") launches `tidewatch --from-stdusk <socket>`: with a window already running (same home) it is forwarded as `adopt-stdusk <socket>` (answered `ok` or `closing` like the others) and the launch exits; with none, or after a `closing` window is gone, that launch becomes the window and receives at startup. The window receives on a job thread (`from_stdusk.rs`) and makes each pane a shell tab in the group of the git repo its folder is in (an existing group, else a new one; a linked worktree counts as its main repo; folders in no repo share one Other group), the pane that had focus active; on a failure it adopts nothing, shows a notice, and stdusk keeps its window. To check it in the background: start a `TIDEWATCH_BACKGROUND=1` run with a short throwaway `TIDEWATCH_HOME`, `TIDEWATCH_DEV_STATUS_LOG=1` and a `TIDEWATCH_DEV_QUIT` long enough, in a throwaway repo, then run `cargo run -p tidewatch --example fake_stdusk -- <built tidewatch> <folder>...` (no `TIDEWATCH_BACKGROUND`, same `TIDEWATCH_HOME`; it spawns a shell per folder, the last holds focus, sends them and prints their pids and `acked`): the pids stay alive with parent 1 until the window quits, the status log shows `shell adopt-stdusk <socket>`, and `session.toml` (via `TIDEWATCH_DEV_QUIT`) has a shell tab in the right group (check six folders: repo A root, A subfolder, a linked worktree of A, repo B, two non-repo folders -> A with 3 shell tabs, B with 1, one Other with 2; start the window with `PATH=/usr/bin:/bin` to check git resolves in a thin launch environment; the strip shows only the front group, so pass the folder of the group to look at last, it holds focus; `TIDEWATCH_DEV_TRUST=no` dismisses the folder-trust modal in a fresh home); add `TIDEWATCH_DEV_SHOT=<png>` to see it. Kill everything you started. A background run from `/` with `last-workspace.toml` seeded in a throwaway `TIDEWATCH_HOME` shows the folder pick (read the window's `dir` in `session.toml`). With nothing remembered the window shows the welcome screen (Open repo, Cmd+O, and the repos of an old `session.toml`) instead of a shell in `/`; opening a repo from it replaces it, and it saves nothing while it shows. The socket is `<home>/.tidewatch/.state/instances/tidewatch.sock`, so a `TIDEWATCH_HOME` run never meets the real one, but a socket path must stay under about 100 bytes: use a short throwaway home such as `/tmp/x`, not one under macOS `$TMPDIR`. Quake is on by default (`Ctrl+Alt+Grave`, Settings, General, Window). **Never live-test quake show/hide, the hotkey or the menu-bar item from an agent run: they take focus. A background run (below) gets none of them by construction (`shell_plan::Plan`).** To see a background instance answer a launch without any window action: start it with `TIDEWATCH_DEV_STATUS_LOG=1`, then run `tidewatch --toggle` or `tidewatch <repo>` with the same `TIDEWATCH_HOME` and read its stderr (`shell toggle`, `shell open <repo>`).
Screenshot runs open in the background: no Dock icon, never take keyboard focus from the
developer's active window. `TIDEWATCH_BACKGROUND=1` does the same for any other dev or live-check
run. Agents must use one of the two for every window they open.
`TIDEWATCH_SCREENSHOT_WAIT=<seconds>` waits longer before the capture (default 1.5s).
`TIDEWATCH_DEV_WORKTREE=open|ask|delete` opens one worktree tab at startup; `ask` also shows its close
dialog (Enter in it deletes the branch), `delete` closes it with "Delete branch". Use a throwaway repo, and a temp `HOME` (with
`ZDOTDIR` set to it) so worktrees land in a temp `~/.tidewatch`, never in the real home.
`TIDEWATCH_DEV_SCOPE=whole` starts the graph on Whole repo, `TIDEWATCH_DEV_PANEL=progress|changes|history` shows that side of the History card, `TIDEWATCH_DEV_SEARCH=<text>` types it into the commit search (field focused, first match selected; `TIDEWATCH_DEV_PRESS=find-commit@<s>` presses Cmd+F, `back-to-terminal@<s>` presses Esc), `TIDEWATCH_DEV_PICK=<row>` selects a graph row,
`TIDEWATCH_DEV_OPEN=commit|file|file:<n>` opens the selected row's files in the tree (and file n, 0 first, in the file view), `TIDEWATCH_DEV_PRESS=<command id>@<seconds>,...` presses those table commands (`file-view`, `back-to-terminal`, `next-file`, `prev-commit`...) through the real key path (`move-sessions` has no chord, so it runs directly), `TIDEWATCH_DEV_NOTE=<text>` writes a note on the first added line of the first diff shown (saved like a real one), `TIDEWATCH_DEV_NOTES=[<row>@]<path>:<line>[-<last>]:<text>|...` adds notes to the draft review once the tab's notes have loaded (`<row>@` puts a note on that graph row's commit, a range makes it a block note), `TIDEWATCH_DEV_NOTE_SPAN=<n>` makes the `TIDEWATCH_DEV_NOTE` note cover `n` more lines, `TIDEWATCH_DEV_COMPOSER=<line>|<first>-<last>` opens the note composer on those lines of the file view, `TIDEWATCH_DEV_SIDE=<fraction>` (0.3 to 0.75) starts with the left column that wide, to check the file view narrow, and `TIDEWATCH_DEV_WINDOW=<w>x<h>` (600 to 4000 points each) opens the window that size, to check a view in a short or wide window.
Notes live in `<home>/.tidewatch/.state/<repo-dir>/<tab>/notes.json`; the main tab's key is `main`.
`TIDEWATCH_HOME=<dir>` keeps `.tidewatch` and `.config/tidewatch` in `<dir>` while `HOME` stays real, so agent
CLIs keep their login. `TIDEWATCH_DEV_AGENT=<profile id>` opens that profile in a new tab at startup, ready for its first
message (level from `TIDEWATCH_DEV_LEVEL`; a level the group refuses, such as YOLO in Other, is reported on stderr and
nothing starts). `TIDEWATCH_DEV_TASK=<text>` types into that tab's composer and
`TIDEWATCH_DEV_START=1` also sends it. `TIDEWATCH_DEV_DIALOG=choose|agent|<profile id>|1`
opens the new-tab form (a draft tab) as an agent form or on that pick (`TIDEWATCH_DEV_FORM_MESSAGE=<text>` types a first message into it so the worktree name follows it, and `TIDEWATCH_DEV_START=1` also presses Start), and
`TIDEWATCH_DEV_SCROLL_KEEP_AWAKE=1` scrolls the General page to the Keep awake card, `TIDEWATCH_DEV_SCROLL_CHECKLIST=1` to the Checklist card, `TIDEWATCH_FAKE_OVERVIEW=<n>` fills the Overview with twelve stand-in agents (n working) and `TIDEWATCH_FAKE_OVERVIEW_REPO=<name>` picks a repo chip, `TIDEWATCH_DEV_SETTINGS=1` the profile editor, for captures (use `TIDEWATCH_SCREENSHOT_WAIT=6`: profiles load and
versions are probed in the background). Check an agent tab with `ps -o args= -p $(pgrep -n claude)`.
`TIDEWATCH_DEV_GH_DIR=<dir>` puts `<dir>` first on the PATH `git` and `gh` run with, for a fake `gh` script (the real GitHub API must
never be reached from a check). `TIDEWATCH_DEV_AUTO=1` holds the review until the agent is idle, `TIDEWATCH_DEV_SEND=one|all` sends the first note or the whole
review (`TIDEWATCH_DEV_SEND_MESSAGE=<text>` is its message), `TIDEWATCH_DEV_DELIVER=ask|asked|missing` presses the pull request card's Ask button, or shows the `Asked` or `No pull request yet` card without sending anything, `TIDEWATCH_DEV_PR=pull|ask|post`
pulls the PR's comments or opens (and confirms) the post dialog for the first note, each once, as soon as the active tab is ready.
`TIDEWATCH_DEV_OVERVIEW=1` and `TIDEWATCH_DEV_FOCUS=1` start on the Overview or in focus mode; `TIDEWATCH_DEV_STATUS_LOG=1`
prints every hook and status change (and each keep-awake take and release) to stderr with a wall-clock time in ms; `TIDEWATCH_DEV_KEYS='\e[B\r'` (after
`TIDEWATCH_DEV_KEYS_AFTER` seconds, default 8) types into the newest agent tab once, for Claude's folder-trust prompt; `TIDEWATCH_DEV_PASTE='text\nmore'` (same delay) injects one `Event::Paste`, so it lands in the focused field or terminal (`TIDEWATCH_DEV_READER=raw` for the terminal).
`TIDEWATCH_DEV_SETTINGS=trust` the Folder trust page, `TIDEWATCH_DEV_SETTINGS=general` the General page, `TIDEWATCH_DEV_SETTINGS=shortcuts` the Shortcuts page, `TIDEWATCH_DEV_SETTINGS=house` the House style page, `TIDEWATCH_DEV_SETTINGS=dirty` the profiles with an unsaved edit (the save bar), `TIDEWATCH_DEV_PALETTE=<query>|1` opens the command palette filled with that query (use `TIDEWATCH_SCREENSHOT_WAIT=7`: profiles load in the background), `TIDEWATCH_DEV_STATUS_LOG=1` also prints each command a key ran, `TIDEWATCH_FAKE_UPDATE=<version>` shows an update (pill and Settings line; the run makes no check and installs nothing; with a cask install a click on the pill would still run `brew upgrade`, so never click it), `TIDEWATCH_FAKE_UPDATE_STATE=failed|stuck|confirm` shows a failed update (orange `Update failed` chip, the error in Settings), a stuck one (`Update stuck · Fix`, the repair script in Settings) or a stuck one with the Fix confirm open (the run is offline; Quit and fix only toasts the script and never starts the helper, so it is safe to click, but never unset the switch and click Fix in a copy installed with Homebrew), `TIDEWATCH_DEV_SCROLL_UPDATES=1` scrolls the General page to its Updates card, `TIDEWATCH_DEV_TRUST=yes|no|undo` answers the first-launch folder trust question once (a fresh `TIDEWATCH_HOME` otherwise shows the dialog; nothing is written until yes).
`TIDEWATCH_DEV_PR_EVENTS=<json>` loads the PR cards of the first agent tab from a file (a `Cards` value, see `pr_cards.rs`) instead of its state folder; without `TIDEWATCH_DEV_GH_DIR` as well it also turns off every look, Re-run and page opening, so nothing in the cards reaches the outside (a click on Open on GitHub only toasts the address). With a fake `gh` in that directory the looks run against it (it answers `pr view <n> --json ...`, `run view ... --json jobs`, `run view ... --log-failed`, `api repos/...`). `TIDEWATCH_DEV_PR_POPOVER=1` keeps the strip's popover open. Check it with a stand-in `claude` that writes a transcript under a throwaway `HOME` (timestamps near the cards') and posts hooks; never a real `gh` or a real PR.
`TIDEWATCH_FAKE_SERVICES=1` stands in three repo services (`db` running, `api` running, `tunnel` crashed, with fake log lines; nothing is spawned or written), `TIDEWATCH_DEV_SERVICES_POPOVER=1` opens the services list, `TIDEWATCH_DEV_SERVICES_SELECT=<name>`, `_MENU=<name>`, `_DIALOG=add|remove` and `_LOGS=<name>` select a card and open a dialog or the Logs view, `TIDEWATCH_DEV_SERVICES_AUTOSTART=1` lets a screenshot or background run start its saved services (it starts none otherwise),
`TIDEWATCH_FAKE_JOBS=1` (`done` or `idle` also treats every agent as done or as not working, so quiet jobs close as ended or show as muted lines) gives every agent tab six jobs (the orders backfill at 21.2% with samples, checks 3 of 5, an import stuck at 97.4% for six minutes, a finished test run, a name-only worktree setup, a timed deploy) and saves nothing: the tab's bar and percent, the Progress panel's cards and the Overview card's `21% · 1h 51m` line. A real script writes `{"name","done","total","unit","phase","state"}` lines to the file in `$TIDEWATCH_PROGRESS` (`<tab state>/progress-feed.jsonl`), and a house-bar line on the terminal (`label [####----] 42.1% done/total`) is read too. `TIDEWATCH_FAKE_AVATARS=1` gives the agent tabs the seven mockup icons in turn, round (the tab, the Overview card's face and ring and the History card's header; the third is too dark on purpose and shows the letter; nothing is saved). An agent's `set_avatar` draws the same, saved in the tab's `avatar.json` (a call is refused until Draw avatar or Redraw for that tab, or a pending Redraw ask, armed it); Redraw sends the agent `avatar_ask::ASK` through the existing send path (`avatar_redraw.rs`): a busy agent is not refused, the ask is held and typed when the agent is idle, then a toast says `Asked <name> to redraw its icon`; Use letter removes the file. A letter tile's menu offers Draw avatar, the same send path with `avatar_ask::ASK`. No tab is asked to draw on its own: the right-click Draw avatar is the only ask, and a tab with no picture keeps its letter face. `TIDEWATCH_FAKE_PARKED=1` opens three agent tabs (backfill-orders, fix-ci, review-auth) and parks three more (migrate-billing for its job, flaky-tests for a date, docs-sweep for idle), the three reasons as the mockup words them, with stand-in shells and no agent; the rules are off so they stay, and with `TIDEWATCH_DEV_PARKED_POPOVER=1` the list is open; `TIDEWATCH_FAKE_PARKED=visible` opens the same six unparked and leaves the rules on, so a narrow window parks what does not fit. Use them with `TIDEWATCH_FAKE_AVATARS=1` and `TIDEWATCH_FAKE_JOBS=1`. `TIDEWATCH_DEV_PROGRESS=<file>` gives the first agent tab the progress ledger in that markdown file (the format of `progress.rs`) instead of reading its own `progress.md`; nothing is written for it, but its scheduled items show up in the in-memory Coming up list. A real agent's `update_progress` replaces it. With `TIDEWATCH_DEV_OPEN_SCHEDULED=<tab>` does once, when the profiles are loaded and the restore is done, what a click on that tab's Coming up card does (select it, or reopen it from its schedule entry); with the schedule index read from a real file it needs a run that is not a screenshot run, so keep the items a few days off or the desktop notice fires. With `TIDEWATCH_DEV_STATUS_LOG=1` every ledger an agent sends prints a `progress tab=... state=... phase=... done=a/b scheduled=n coming_up=n` line to stderr.
`TIDEWATCH_DEV_HOVER_FILES=1` reports a file dragged over the window on every frame, to capture the reply box's drop highlight (files dropped on the Reader go into the reply box, pictures as chips; on a terminal they are typed as paths). `TIDEWATCH_DEV_HOVER=<x>,<y>` moves the pointer to that point of the window on the first frame and leaves it there, to open a tooltip in a capture (with `TIDEWATCH_SCREENSHOT_WAIT=4`). `TIDEWATCH_FAKE_MEESEEKS=named` makes the first three agent tabs Meeseeks with a task, a Claude session title and (the first and third) a chosen name, to check the labels (pair it with `TIDEWATCH_FAKE_PARKED=visible`). `TIDEWATCH_FAKE_MEESEEKS=on|struggling|poofed|readonly|promoted` shows the Meeseeks states for captures (`readonly` is a read-only Meeseeks 4 minutes in, `promoted` the same task after promotion; pair either with `TIDEWATCH_DEV_PROGRESS=<ledger file>` for the stage bars): `on` makes every agent tab a Meeseeks 12 minutes in at turn 9 with its tests running (the stage card in Progress, the fixed face), `struggling` one with 3 failed checks (the orange tab and the Take over / Give up card), `poofed` fills the Overview's Poofed today with two stand-in entries and toasts once (`TIDEWATCH_FAKE_POOFED_READONLY=1` makes the first a read-only one with a long prompt, a markdown answer and an empty branch); no check runs, nothing is pasted or removed, and the poofed file is neither read nor written (use it with `TIDEWATCH_SCREENSHOT` or `TIDEWATCH_DEV_SHOT`: a plain run would save the stand-in state in `session.toml`). `TIDEWATCH_DEV_DIALOG=meeseeks` opens the new-tab form on Meeseeks (`TIDEWATCH_DEV_FORM_MESSAGE` takes one task per line, `TIDEWATCH_DEV_START=1` presses Summon). A capture of the Overview lists the real agent sessions of the machine under Running elsewhere: run it with a throwaway `HOME` and `ZDOTDIR` (and a stand-in `claude` first on `PATH`), never with the real home.
`TIDEWATCH_FAKE_LIMITS=31@2h,84@3d` stands in the 5-hour and weekly plan limit readings (a percent and the time until the reset, `h` or `d`) for the status bar's two meters and save mode (a real run reads them from the `plan-limits.json` that each Claude tab's status line command saves), and `TIDEWATCH_FAKE_TOKENS=1` gives every agent tab 1.2M tokens and `$20.51 this session`; nothing is read or saved for either. To check the status line command by hand: `echo '<status line JSON>' | tidewatch --statusline <dir>` with `CLAUDE_CONFIG_DIR` at a throwaway folder whose `settings.json` holds a `statusLine` command: it writes `<dir>/plan-limits.json` and prints what that command printed. A `TIDEWATCH_DEV_HOVER` capture of a status bar meter did not show its tooltip in a background run (checked with the 5h and week meters), so the tooltips are covered by the headless test.
`TIDEWATCH_FAKE_CLOSED=1` adds three stand-in rows to the Recently closed section of the Overview, folded out, for captures (nothing is read or reopened). `TIDEWATCH_FAKE_MEESEEKS=on|struggling|poofed` shows the Meeseeks states for captures: `on` makes every agent tab a Meeseeks 12 minutes in at turn 9 with its tests running (the stage card in Progress, the fixed face), `struggling` one with 3 failed checks (the orange tab and the Take over / Give up card), `poofed` fills the Overview's Poofed today with two stand-in entries (checks, last turn and ledger stages included), opens the first as a summary tab (a stand-in branch, no git) and toasts once; no check runs, nothing is pasted or removed, and the poofed file is neither read nor written (use it with `TIDEWATCH_SCREENSHOT` or `TIDEWATCH_DEV_SHOT`: a plain run would save the stand-in state in `session.toml`). `TIDEWATCH_DEV_DIALOG=meeseeks` opens the new-tab form on Meeseeks (`TIDEWATCH_DEV_FORM_MESSAGE` takes one task per line, `TIDEWATCH_DEV_START=1` presses Summon). A capture of the Overview lists the real agent sessions of the machine under Running elsewhere: run it with a throwaway `HOME` and `ZDOTDIR` (and a stand-in `claude` first on `PATH`), never with the real home.
`TIDEWATCH_DEV_READER=raw` starts agent tabs on the raw terminal, `TIDEWATCH_DEV_READER_KEY=<s>` presses Cmd+Shift+T after that many
seconds through the real key path, `TIDEWATCH_DEV_ANSWER=allow|deny` clicks a permission button once, `TIDEWATCH_DEV_PICTURES=<path>:<path>` attaches those pictures to the message box once (as chips), `TIDEWATCH_DEV_REPLY=<text>`
(`_REPLY_AFTER=<s>`) sends a reply from the Reader's box, `TIDEWATCH_DEV_QUESTION=open,pick2,next,all,type:text,send,skip,fold` drives the live question card one step every 0.4 s (a new question opens folded, so `open` comes first; `pick`, `next`, `space` and `down` do nothing while it is folded), `TIDEWATCH_DEV_ASK=1` puts a stand-in question with three options in the Reader as an `ask_user` call nobody answers (with a stand-in `claude` that writes a transcript under a throwaway `HOME`, and `TIDEWATCH_DEV_AGENT=builder TIDEWATCH_DEV_LEVEL=yolo TIDEWATCH_DEV_AUTOPICK_SECS=45` for the countdown, it captures the folded and the open card). Run Claude checks with `CLAUDE_CODE_FORCE_SESSION_PERSISTENCE=1` when the
shell that starts Tidewatch is itself a Claude session: the child otherwise writes no transcript and the Reader falls back to the terminal.
Session: every change is saved to `<home>/.tidewatch/.state/session.toml` and the next launch restores it (Settings, General, turns that off). To check it in the background: `TIDEWATCH_DEV_QUIT=<s>` closes the window through the close request (the quit-time save runs), `TIDEWATCH_DEV_SAVE_DEBOUNCE_MS=600000` leaves that quit-time write as the only one, `TIDEWATCH_DEV_SELECT=<n>` (`_SELECT_AFTER`) selects tab n, `TIDEWATCH_DEV_SHOT=<png>` (`_SHOT_AFTER`) saves a screenshot without quitting (the screenshot harness itself saves nothing), `TIDEWATCH_DEV_LEFTOVERS=open|clean` opens the leftover worktrees dialog or presses Clean up. The last run's end decides a resume: `.state/running` stays when a run is killed, so a relaunch types the resume command instead of running it (`resume_agents` in `settings.toml`: auto, prefill, off). A YOLO tab is always typed, whatever the mode and however the run ended (Off keeps it a plain shell): it resumes with the full YOLO launch of its profile and waits for Enter. A YOLO tab outside a worktree is still refused by `launch_command` and reopens as a shell with that reason. Relaunch with the same `TIDEWATCH_HOME` and repo; `TIDEWATCH_DEV_REPLY` asks a resumed agent a question from the Reader.
Keys (macOS; Linux uses Ctrl+Shift or Alt, the table is `commands.rs` and `docs/shortcuts.md`, and a change goes in the table first): Cmd+Shift+P the command palette, Cmd+T new tab (a draft tab whose left column is the form: Agent, Meeseeks or Shell with A, M or S, a Meeseeks form takes one task per line, ticks Done means (Tests pass, Work committed, Open a PR) and Summon N opens N tabs, a lane of profiles (1-9, Up and Down; a Meeseeks lane lists the agent CLIs, 1-4, and always runs YOLO with that CLI's Builder profile, so it has no permission row and Left and Right do nothing), Left and Right the permission level, the worktree name and start branch, the first message; Cmd+Enter starts, Esc closes the draft; nothing exists until Start, and the bare keys only work while no text field has the keyboard), Cmd+O open a repo, Cmd+W
close the active tab (not the pinned main tab; a worktree tab asks keep/delete branch first), Cmd+1..9 select (in the repo on show), Cmd+Shift+K parks the active tab (Linux Ctrl+Shift+K; the selection goes to its neighbour, and a parked tab comes back when you open it from the Parked pill or the palette, when its agent needs you, its job ends or stalls or its date arrives), Cmd+Shift+Left / Right move the active tab one place within its repo (Linux Ctrl+Shift+PageUp / PageDown; the terminal does not forward either, but a focused text field takes Cmd+Shift+Left itself, so the chord waits for `Focus::TextField` to end, and for any dialog, Settings, the palette or the Overview; a tab can also be dragged along the strip), Cmd+Ctrl+] / [ next and previous repo,
Cmd+F the commit search (only while the History side of the card shows; Ctrl+Shift+F on Linux), Cmd+Shift+T flip the active agent tab between the Reader and the raw terminal, Cmd+, the profile editor, Cmd+0 the Overview (Esc or Cmd+0 closes it), Cmd+. focus mode (hides History and Diff), Cmd+= / Cmd+- interface bigger / smaller and Cmd+Shift+0 back to 100% (Linux Ctrl+Shift; egui's own keyboard zoom is off, the size is saved as `ui_zoom`; the drop-down unzooms its viewport commands in `quake::unzoom`). Panels (Settings, General, Window; `[window] panels` in settings.toml, `side` by default or `below`): side by side puts History on the right at full height, a click on a commit opens its files under its row and a click on a file shows its diff (notes, Unified/Split, Send, Post to PR) in the terminal's place under a Terminal chip, with the agent still running; Below keeps the old terminal over History and Diff. File view keys (only while the file's diff has the keyboard and no note is being typed, so the terminal and text fields keep Esc, arrows and brackets): Esc back to the terminal, Cmd+J (Linux Ctrl+Shift+J) flips between the terminal and the last opened file, Up and Down the previous or next file of the open commit, [ and ] the previous or next row of the tree.
`TIDEWATCH_FAKE_SUBAGENTS=1` lists four running agents and one finished above the Reader's reply box of every Claude agent tab, in the tab tooltip and on its Overview card (nothing is read or written); `=folded` starts those lists folded to their header. Pair it with a stand-in `claude` that writes a transcript under the throwaway `HOME` so the Reader shows (`TIDEWATCH_DEV_AGENT=builder`, `CLAUDE_CODE_FORCE_SESSION_PERSISTENCE=1`, `TIDEWATCH_DEV_WINDOW=700x800` for a narrow column).
`TIDEWATCH_DEV_SUBAGENT_OPEN=<index>` opens the chat of the row at that index of the front tab's agents list as soon as the Reader shows (with `TIDEWATCH_FAKE_SUBAGENTS` its rows read the redacted `subagent_running` and `subagent_finished` fixtures: rows 0 to 3 running, 4 finished); the screenshot harness cannot hold a hover, so the row tint is covered by a headless test.
